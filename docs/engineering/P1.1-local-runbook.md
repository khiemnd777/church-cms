# P1.1 — vận hành cục bộ

Scope: synthetic data, loopback only. Không dùng các lệnh này với server/data production. Không thay đổi trust store/global settings. Bun1.3.1; dependency versions chính xác trong package.json/bun.lock. Mongo8.0.16 replica set/Redis7.4.6 là dịch vụ cục bộ riêng.

## Khởi động

1. `bun install --frozen-lockfile --ignore-scripts`
2. `bun run local:setup` — tạo `.env`0600/certificate30ngày trong `.local`, không in secrets. Chạy lại không ghi đè.
3. `docker compose up -d --wait`
4. Lần đầu: `docker compose exec -T mongo mongosh --quiet --eval 'rs.initiate({_id:"church-local",members:[{_id:0,host:"localhost:27017"}]})'`. Khi replica set đã init, không lặp initiate; db:init kiểm tra readiness với thời gian chờ hữu hạn.
5. `bun run db:init` — tạo/đối chiếu validators/indexes trên local Church CMS DB, không tự chạy lúc HTTP startup.
6. Trong terminal tương tác riêng: `bun run owner create owner@example.test 'Owner thử nghiệm'`. CLI in mật khẩu tạm đúng một lần cho người vận hành, không redirect/log/screenshot. Owner là danh tính riêng, không account tenant. Chỉ dùng account synthetic; không tự bàn giao cho người thật.
7. `bun run dev` — build rồi chạy `https://localhost:3443/owner/login`. Backend phục vụ bundle cùng origin; API bind127.0.0.1. `bun run build` rồi `bun start` dùng lại bundle.

Certificate server được ký bằng CA riêng tại `.local/root-ca.pem`, chỉ dùng local. API tests tin đúng CA này một cách tường minh, không tắt TLS verification. Browser cần trust certificate trong môi trường kiểm thử riêng; chưa cài trust host/global. Không dùng bypass TLS làm bằng chứng auth. Có thể tái tạo certificate local sau khi hết hạn: di chuyển riêng bộ TLS do dự án sinh ra trong `.local` rồi chạy setup, không đổi trust global.

Sau đăng nhập temp phải đổi password8–128 Unicode code points, không trim, tối đa512bytes. Đây là blocklist nhỏ cục bộ có version, không tuyên bố bao phủ mọi mật khẩu lộ. Hash argon2id64MiB/3/p1, tối đa4 hash/verify đồng thời; vượt trả503, không giảm cost. Sessions Mongo authoritative: full8h/idle15m; limited min15m/temp expiry24h; CSRF HMACversion1, cookie realm riêng. Reauth giữ hạn absolute. Chỉ activity foreground mới touch; polling me không touch.

## Kiểm tra và chẩn đoán

- `bun run lint`, `bun run typecheck`, `bun run build`, `bun test tests`; tests tạo DB `church_cms_test_<random>`, chỉ xóa DB do chính test đó tạo.
- `bun run test:browser` build bundle rồi dùng image Firefox/Bun riêng; cert/profile chỉ trong container, source/build mount read-only, không mount `.env`/private key host. Ảnh và báo cáo tại `output/p1.1-*`, container bị gỡ sau khi sao chép kết quả. Cần Docker Desktop và khả năng kéo image; user không đặc quyền, không bypass TLS hoặc tắt browser sandbox. Responsive desktop/mobile trong Firefox, chưa chứng minh thiết bị thật/Safari.
- `bun run benchmark` đo hash/verify ở concurrency1/2/4; ghi máy/Bun/RSS, không suy ra SLA production.
- `/api/health/live` sống không phụ thuộc DB; `/api/health/ready` kiểm tra Mongo replica set/transaction/indexes và Redis.
- Logs chỉ requestId/route ID/method/status/latency. Không request body/header/cookie/email/password/hash. HTTP 503 khi dependency fail, không cache quyền để cho qua. Redis commands timeout1500ms, không queue offline/reconnect vô hạn; sau khi Redis phục hồi, khởi động lại API để nối lại.
- Muốn dừng: Ctrl-C server; `docker compose stop` giữ volume. `docker compose down` gỡ đúng container/network, vẫn giữ volume. Không `down -v` theo runbook thường ngày.
- CI file chỉ cấu hình trong workspace; chưa có Git repository/remote nên remote CI NOT_RUN. No publication/deploy.
