## C36-01 — Buổi tham chiếu rõ ràng

Attendance sở hữu `reportingKind: general | sunday_reference`; bản cũ không có trường được đọc là `general`, không tự phân loại/backfill. Buổi tham chiếu phải church scope, ngày Chúa nhật, không phải buổi lớp dự bị. Partial unique `(churchId,heldOn)` với filter `reportingKind=sunday_reference` giữ tối đa một nguồn/ngày, cả draft/open/closed. Trùng trả409 `ATTENDANCE_REFERENCE_EXISTS`; không tự thay buổi cũ. Bỏ chọn buổi cũ rồi chọn buổi mới là hai lệnh tường minh.

Đổi reportingKind của buổi đã tồn tại cần reason + `referenceConfirmed:true`, If-Match/CAS, idempotency key, fresh manager/tenant fence; metadata/history/audit/ledger cùng transaction. UI cho rà và xác nhận trước lưu. Đổi phân loại không sửa roster, presence, generation hoặc lịch sử chấm. Buổi non-draft tiếp tục khóa heldOn/scope/unitId theo P3.1. DB validator bổ sung enum/quan hệ scope và partial index; áp dụng chỉ trên UUID test DB trong gói này, chưa init/migrate main DB.

## C36-03 — Workflow, tải và phục hồi có giới hạn

- `scripts/p36-workflow.ts` chạy public commands thật: dữ kiện dự bị tường minh → cấp thẻ → resolve/scan QR qua Attendance → chốt thờ phượng → ghi danh/active khóa → buổi học/chốt/credit → phỏng vấn thủ công → rite Báp-têm/canonical fact → draft/prepare/issue hai artifacts → đối soát Overview/W14/hashes. Không dùng kết quả học để tự ghi Báp-têm.
- `scripts/p36-qualification.ts` đo100/500/2000 profiles ×1/5/10 workers; mỗi worker2 warmup+10 measured journeys; tổng480 measured journeys/1920 measured HTTPS requests. Mỗi journey đọc W01, W02 absent3 page25, W14, W04. Volume fixture trực tiếp trong DB allowlist synthetic:12closed church references,10areas ×4closed own-unit sessions; tách khỏi workflow public-command. Không gọi dữ liệu volume là lịch sử đã tạo qua API.
- Explain kiểm Sunday partial unique, member lookup unique và own-unit/date trên fixture đại diện. Latency là số đo local, không production SLA hoặc cam kết capacity. Không đo đủ mọi phối hợp payload/tenant/replica.
- Quiesce HTTP trước `mongodump --archive --gzip`; target là UUID DB mới trống, namespace remap, không `--drop`. So toàn bộ34collections: documents/binary hashes theo canonical EJSON, indexes theo thứ tự key/options, validators. Sau khi so khớp mới revoke restored sessions, purge certificate_previews, đổi synthetic signing/CSRF key. Kiểm old cookies/proof/preview bị từ chối, fresh owner/secretary login, active QR resolve, canonical Báp-têm, PDF/DOCX hashes, revoke/download-denial. Không restore Redis hoặc flush shared Redis.
- Finally chỉ drop đúng hai UUID DB sở hữu, dừng listener riêng, xóa private CA/archive. Browser wrapper chỉ dọn container của chính lần chạy. Readback namespace/private paths/containers trước bàn giao; không dừng shared Mongo/Redis hoặc sửa volumes.

Lệnh: `bun test --timeout 30000 tests`; `bun run typecheck`; `bun run lint`; `bun run ui:check`; `bun run build`; `bun run build:ui`; `bun audit --json`; `bun run test:browser:p3.6`; `bun run qualify:p3.6`. Browser regression dùng `CHURCH_EVIDENCE_DIR=output/p3.6/regression/<suite>` cùng wrapper hiện có, giữ bằng chứng P3.1–P3.5.

Receipt/result/latency/restore/ảnh tại `output/p3.6/`; đây là snapshot local, self-review, chưa nghiệm thu hay released. Không suy RPO/RTO/PITR/production recovery từ bản dump quiesced.
