## Time, recurrence và conflicts

End must be after start, ≤24h; overnight explicit endDay. Once, weekly weekdays/interval1–4, monthly weekday/ordinals1–5; until within365days inclusive/≤200generated, no duplicate weekday/ordinal, no empty expansion or silent truncation. Week anchored Sunday; monthly fifth missing skipped. Six Sunday default starts nearest Sunday not before today; week Sunday–Saturday matches existing project convention.

draft/scheduled/cancelled. Past means startAt≤now, correction one requires reason, unchanged day/start/end/scope/unit/state; metadata only. New future input must start after now. A series alteration applies by original slot order, retains started rows and explicitly reviews private exceptions. Assignment identity is member ID (not account); external name is snapshot only. No age>=16 rule or demo fallback person.

Only scheduled overlaps by same member/choir ID produce warnings; [start,end) allows adjacent events. Each candidate excludes replaced occurrence IDs. Every writer atomically advances schedule_state revision after recomputing proposal, serializing same-tenant inserts/edits and preventing snapshot write skew. Sources newly assigned are fenced. Existing unchanged identities retain snapshots rather than silently relabeling old assignments. Names/locations typed as text cannot certify identity or venue booking.

Domain/history/audit/Operations v2 same transaction. Ledger safeResult IDs/count only; replay/receipt checks fresh manager/resource auth. Retries use same intent/key; UI pending is memory-only, blocks navigation, reconcilable after reauth. No success fallback on timeout.
